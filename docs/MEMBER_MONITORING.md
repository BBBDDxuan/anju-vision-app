# 成员监护、人脸录入与家庭联系人（1.3.0）

成员监护页以成员列表为入口，点击后进入成员详情。详情集中展示姓名、关系、备注、人脸资料和关联事件，设备范围折叠展示。家庭联系人与被监护成员分别管理。

## 共享档案和旧数据

创建、编辑和删除成员需要连接配套的新 website 后端。连接同一电脑的手机共享档案；手机保留按后端地址隔离的离线缓存。离线可以查看缓存，恢复连接后下拉刷新。切换后端不会自动将成员复制到另一台电脑。

旧版手机档案不会自动上传。成员页选择“将旧档案复制到电脑”并确认后，复制姓名、关系、备注和设备范围；原档案留在手机。导入先保存旧ID到新随机ID的映射，重试不会再创建同一份档案。不同手机各自导入前仍应核对是否已有同一家庭成员。

## 录入人脸

1. 在 website 根目录运行 `.\.venv\Scripts\python.exe scripts/prepare_face_models.py --check` 检查模型；缺失时显式运行同一命令去掉 `--check`，下载约37.1 MiB模型。当前电脑已有模型时无需重复下载。
2. 重启电脑后端。默认本地 `FACE_RECOGNITION_ENABLED=true`；云部署不开放人脸或家庭档案接口。配置信息见 website 仓库 `docs/MEMBER_FACE_RECOGNITION.md`。
3. 手机进入“成员监护 → 成员详情”，取得该成员同意并勾选确认。选择已拍好的 JPEG/PNG 照片，建议正脸与不同角度3–5张，每张只包含一个人，每张最多5 MiB，单成员最多10张。
4. 电脑提取并保存人脸特征，录入原照不保存到后端。手机中用户原有照片保留。清除人脸资料会保留成员档案和安全事件；删除共享成员会一并删除该成员人脸特征。

人脸结果作为需核对的身份候选。人脸太小、不可见、多个人物框重叠、匹配有歧义或证据不足时保持“身份未确认”。在事件页可人工关联或取消关联；该人工纠正保存在当前手机。关联摄像头只表示监护范围，不会直接认定摄像头内每个人都是某位成员。

## 联系人提醒

“备用联系人提醒延迟”表示重要告警首次安排主要联系人提醒后，若仍未被确认或处理，等待多久再安排备用联系人提醒。支持30秒、1分钟、3分钟和5–86400秒自定义。已安排事件的期限不会因修改偏好而重新计时。有人确认或处理后取消未发出的提醒。

主要与备用手机在连接设置中选择各自角色。后台推送仍需原有FCM服务配置、有效设备登记和系统通知权限；本功能不自动拨号或发短信。服务商接受推送不等于手机已收到或联系人已查看。前台轮询仍会显示统一告警，不作为联系人已响应的依据。
