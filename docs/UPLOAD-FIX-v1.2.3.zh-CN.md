# v1.2.3 上传错误提示修正

## 已确认的问题

旧版 App 将未识别的 HTTP 400 一律显示为“录像服务拒绝了访问地址，请检查主机白名单与网关配置”。后端视频检查实际使用 INVALID_MP4、VIDEO_ROTATION、VIDEO_DURATION、VIDEO_RESOLUTION、VIDEO_STREAM、MEDIA_PROBE_FAILED、INVALID_METADATA 等错误码，旧版未覆盖这些码，造成错误归因。

上传进度达到 100% 仅表示视频字节已经传输，之后仍会调用 `/api/uploads/{upload_id}/complete` 检查容器、轨道、时长、分辨率、旋转信息，并准备回放。全部完成后才将记录写入录像库。检查失败时录像库没有新增记录属于当前流程的结果。

## 本次改动

- App 对上述视频错误给出对应的中文说明和经过校验的错误码，不显示服务端任意原文。
- 仅在服务端确实返回 `Invalid host header` 时提示主机白名单错误。
- 传输完成时明确提示仍在检查格式和准备入库。
- 请求失败时不再同时显示“还没有录像”，避免将读取失败误认为空录像库。
- 本机后端新增拒绝请求和业务错误码日志，不记录令牌、请求体、原始文件名和查询参数。
- 手机启动脚本支持为同一台电脑额外指定本机私有 IPv4 地址，额外地址必须通过本机绑定验证；认证和摄像头本机控制限制继续生效。

## 限制和下一步

本版修正错误提示，没有改变后端支持的视频格式。尚未取得用户失败视频的新错误码，不能声称已修复该视频的入库问题。

手机使用旧 APK 重新上传同一视频后，也可在电脑 `runtime/phone-server/video.log` 查到 `Phone API error` 行，包含路由模板、错误码、状态码。

例如 `VIDEO_ROTATION` 表示后端暂不接受带旋转元数据的视频，`MEDIA_PROBE_FAILED` 表示 FFprobe 无法解析文件。必须依据实际错误码采取对应处理。

本地上传不需要互联网；云端模型分析需要电脑访问模型服务。Firebase 默认关闭，仍不具备已验证的后台云推送送达能力。
