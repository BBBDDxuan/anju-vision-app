# v1.2.6 摄像头连接修复（2026-11-05）

版本 1.2.6+4011，Android ARM64 versionCode 6011，x86_64 versionCode 8011。安装包沿用原正式签名。

## 已确认的现场问题

摄像头 TCP 端口可达，但摄像头对当前手机配置和电脑旧配置的取流请求均返回 RTSP 401。stream1、stream2 的当前配置检查均未通过认证。后端帧数为零，录像子进程退出重试，状态显示 recording_stream_interrupted。端口可达不代表账号认证成功。

## 修改

- 后端在提交配置及恢复未正常运行的监护前，使用 FFprobe 验证 RTSP 认证与视频轨道。验证失败时不保存新配置、不停止已有监护、不启动模型。
- 后端仅返回固定错误码与提示，不转发可能含设备密码的原始工具输出。
- App 明确区分摄像头认证失败与后端 Bearer 令牌失败，补充视频路径、取流超时、工具缺失等提示。
- App 增加正在连接摄像头视频流的状态文案。

## 操作

1. 在摄像头设备管理中核对本地设备账号、设备密码及 RTSP 权限。云平台账号密码和后端访问令牌不能替代设备密码。不需要把密码发送给开发者。
2. App 的摄像头 IP 填设备当前局域网地址（例如 192.168.1.100）、端口填 554、本地用户名按设备实际账号填写、视频路径填 stream1，密码单独填写。
3. 点击连接摄像头并开启后端监护。状态为正在识别、帧数持续增加才表示取流成功。
4. 手机预览与后端监护各自建立取流连接；预览失败时仍应独立检查后端状态。
