## 已完成的业务改动

- 连接表单只有“统一后端地址”和“统一访问令牌”；调用 `/api/connection` 检查版本、认证与模型就绪，模型未就绪与网络失败分别显示。
- 同一地址/令牌用于录像、物品查询、统一告警、设备和联系人兼容 API；不要求用户配置内部 8010。
- 旧配置增加 `connection_version` 迁移标记，优先采用原录像配置；不把旧 8010 的用户令牌直接当统一访问令牌。保留本机成员档案、绑定、搜索与问答开关。
- 新增统一告警 API 和模型，保持 A 的全局 ID、来源、复核状态、处理状态、revision、证据与片内偏移。
- 列表逐页拉完，使用第一页 snapshot_cursor 补齐期间变更；只有完整成功的同步才发布业务快照，失败不前移游标。
- 告警镜像与游标一起持久化，按后端/家庭区分；同 ID 只采用较高 revision，确认/解决响应不会被在途旧数据回退。
- 手机确认/解决后读取服务端返回快照，另一客户端通过 changes 同步。来源撤销保留历史并停用处理入口。
- 消息页增加实摄/上传录像来源筛选；详情显示正确来源、证据和录像偏移，支持带认证的原片定位播放。
- 原录像分析页不再通过旧提醒确认接口冒充统一处理；“查看并处理统一告警”定位同视频、原提醒 ID 对应的未撤销中心记录。
- C 使用唯一业务同步流与带作用域的详情入口；统一模式不走旧 controller/app 的危险通知发送路径。
- App 恢复前台时重读录像任务和告警，退出不会请求取消已提交服务器的分析任务；上传取消仍只取消上传会话。
- 原上传、取消、分析、进度、暂停/继续、物品与证据功能复用，未做无关页面美化。

接口与 C 的接点见 [B到C接入说明.md](B到C接入说明.md)。A 的兼容问题见 [交给A的问题.md](交给A的问题.md)。文件和 SHA-256 见 change-manifest.json。
