# 成员档案与人工关联

## 使用

1. 启动更新后的本地后端和网页；手机参与时使用现有 start-phone.ps1，App 连接同一电脑和令牌。不要同时启动两个占用 8000 端口的服务。
2. 网页选择“家庭成员”；App 选择“成员监护”并编辑档案。设置名称、颜色、字母或简写，也可保留关系、备注。头像位置为纯色字母，无照片上传入口。
3. 在“实时摄像头”的“人物候选 · 人工关联”中，核对候选位置和像素化截图，手动选择成员、陌生人、忽略或待确认。候选来自本地人体检测，未检测到人物时不显示候选。
4. 录像须先运行更新后的本地安全分析，以生成 tracks.jsonl。然后在视频回放下方关联当前播放位置的 track；标签从点击时的播放位置开始生效。旧分析没有跟踪索引时，界面会提示重新扫描。
5. 告警使用事件时刻有效的人工关联，显示“姓名（人工关联）”；没有有效关联显示未知成员或待确认。环境火焰不推断为某个人发生危险。历史事件不会被事后新增的标签追溯覆盖。
6. 展开关联分段，查看本次连接/回放的 track、起止位置和标签。关闭回放再打开、切换录像或分析批次，当前候选均需重新确认；旧分段只用于对应文件和批次的历史事件。

## 生命周期与边界

- 复用已有 YOLO 人体姿态框和单路 IoU/中心位置跟踪；没有新增 Re-ID、外观向量、人脸模型调用、外观排序或跨镜头匹配。
- 丢失一次检测、视频跳转/超过 2 秒的画面间隙、人物框明显重叠、断流、停止监护或 30 秒没有新画面，关联失效。暂停录像后反复请求同一位置不会续期；继续播放后需重新选择。
- 标签只对该流、该分析批次、当前 track 的有效时间段生效。位置跟踪可能发生错轨，用户应结合原画面核对；重叠时保守撤销标签。
- 候选整幅缩为 8×12 像素 PNG，供显示和人工核对位置，不保留高清人物 crop。实时候选只在内存保留；录像索引约每 0.5 秒记录框、约每 10 秒记录像素图。原有安全证据录像/图片流程继续沿用。
- 新版主应用强制关闭旧人脸服务的录入、识别和告警自动关联；不受 FACE_RECOGNITION_ENABLED=true 覆盖。既有模型文件、照片和旧数据库数据不会在更新时被删除；清理旧资料仍可通过旧删除接口完成。
- 本地档案仍复用私有档案数据库；manual-tracks.sqlite3 只存人工标签分段与事件标签，data/runs/<run>/safety/tracks.jsonl 存位置和像素化候选，不含生物特征模板。不要提交真实运行数据。
- 云部署关闭人工关联接口。局域网使用已有 Bearer 认证；接口禁缓存并检查 track 版本，陈旧操作返回 409，不能由前端伪造检测框。

## 接口

- GET /api/household/members；PUT/DELETE /api/household/members/{id}，沿用 revision 并新增 label_color（#RRGGBB）、label_letter（最多 2 字）。
- GET /api/manual-tracks/live，读取当前本地摄像头会话。
- POST /api/manual-tracks/video-sessions，JSON {"video_id":"v_..."}，创建独立回放会话。
- POST /api/manual-tracks/{session}/position，JSON {"position_ms":1000}，仅从可信的扫描索引读取人物框。
- PUT /api/manual-tracks/{session}/tracks/{track}，JSON {"version":"...","status":"member","member_id":"..."}；status 也可为 pending、stranger、ignored。
- DELETE /api/manual-tracks/{session}，关闭回放；实时会话由后端管理。

App 修改需要重新构建安装才能使用，刷新网页不会更新手机已安装 APK。此功能的自动化验证使用合成数据，不等同于真实多人摄像头准确率评估。
